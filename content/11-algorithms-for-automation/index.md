# 11. Algorithms for Automation

Translate process rules into explicit validation, transformations, decisions, loops, and state transitions. Add scheduling, retry classification, idempotency, complexity reasoning, tests, and observability so the automation remains understandable under failure.

## Before you begin

Complete [Module 10](../10-use-case-design/index.md) and bring its acceptance criteria. Basic pseudocode is enough; the module builds toward implementation without assuming a specific programming language.

Create an executable reference automation with boundary validation, an explicit state model, an idempotency key, bounded retries, unit and transition tests, structured events, and a short complexity and failure analysis.
