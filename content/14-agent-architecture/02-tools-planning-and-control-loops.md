# Tools, Planning, and Control Loops

## Learning objectives

By the end of this lesson, you can:

- design narrow tool contracts with deterministic authorization;
- implement a bounded observe-decide-validate-act loop;
- compare direct tool choice, router, plan-and-execute, and evaluator loops;
- record useful action traces without depending on hidden reasoning text.

## Tools are capability boundaries

A tool needs:

~~~text
name: lookup_case
purpose: retrieve one synthetic case by exact ID
input schema: {case_id: nonempty string}
output schema: {status, public_fields, source_version}
side effect: none
authorization: caller may read this case
timeout: 2 seconds
errors: not_found | denied | unavailable | invalid_argument
~~~

Use narrow verbs and typed schemas. Avoid tools such as run_sql, execute_shell, browse_any_url, or send_message_to_anyone unless a tightly sandboxed use case truly requires them. Separate read, propose, and commit capabilities.

Tool descriptions help the model choose; they do not enforce policy. The adapter must reject extra arguments, unknown identifiers, cross-tenant access, unsafe URLs, and unauthorized writes.

## The controller owns the loop

~~~text
state = initialize(goal, budgets)
while state.steps < max_steps and state.time_remaining:
    proposal = model.next_action(public_state_and_tool_schemas)
    parsed = validate_schema(proposal)
    decision = authorize(parsed, user, state)
    if decision.requires_approval:
        return needs_input(approval_packet)
    if decision.denied:
        record_reason_and_continue_or_stop()
    observation = execute_tool_with_timeout(decision)
    state = append_structured_observation(state, observation)
    if deterministic_success_check(state):
        return completed(result_with_evidence)
return budget_exhausted_or_failed_safe()
~~~

The controller, not the model, checks completion and budgets. Tool results are also untrusted: a webpage, email, or peer agent can contain instructions attempting to redirect the model.

## Planning patterns

- **Direct selection:** one model chooses one tool; suitable for small, well-separated sets.
- **Router:** classify then send to a fixed specialist workflow.
- **Plan and execute:** propose steps, validate the plan, execute allowed steps, and replan on bounded failure.
- **Evaluator-optimizer:** produce an artifact, score against explicit criteria, revise up to a maximum.

Do not store private chain-of-thought as an audit requirement. Record structured proposal, chosen tool, validated arguments or hashes, result code, evidence references, budget, and outcome.

## Free local practice

Build a controller simulator in Python with no paid model.

1. Define three functions: lookup_case, search_policy, and propose_update. Only the first two are read-only.
2. Define JSON-like input and output schemas plus per-tool timeouts.
3. Use a scripted planner that returns proposals for five fixtures: valid lookup, unknown tool, extra argument, unauthorized case, and repeated loop.
4. Validate each proposal against an allowlist and schema before dispatch.
5. Set maximum steps to five and allow propose_update only to produce a preview.
6. Add a separate commit_update function requiring an explicit approval token generated by the controller, not text supplied by the planner.
7. Log structured action records and verify they contain no synthetic case body.
8. Optionally replace the scripted planner with a local open model only after all controller tests pass. The same policy tests must still pass.

## Completion criteria

You are finished when:

- every tool has a narrow purpose, schema, error contract, timeout, and authority;
- read/propose/commit capabilities are separate;
- unknown tools and extra or unauthorized arguments are rejected outside the model;
- loop completion and budgets are deterministic controller decisions;
- untrusted tool content cannot directly alter permissions;
- writes require an approval artifact the model cannot forge;
- repeated behavior terminates at a bounded state;
- structured traces support replay without storing hidden reasoning.
